# Razor Console

The operator interface for the closed-loop red-team / blue-team payment fraud system.

## Running it

```bash
docker compose up          # from the repository root
```

Console on <http://127.0.0.1:5173>, API on <http://127.0.0.1:8000/docs>. Nothing else needs
installing — not Python, not Node.

Without Docker:

```bash
make dev                   # API and console together
make ui                    # console only, against an API you started yourself
```

`make ui` needs Node 20 or newer. `docker compose up` does not.

## The two modes

**Live.** A backend is reachable. Every number is read from the run's artefacts through the
API, and the interactive controls — scoring, `RUN A ROUND NOW` — execute against the deployed
model.

**Demo.** No backend. Every read resolves against static JSON under `public/demo/`, baked from
the committed `artifacts/default_run/` run. Every chart, every drill-down, every table works. The
controls that *compute* are disabled and say why, because a pre-recorded result of a button
press would be a lie about what the button does.

The mode is decided by probing on boot and shown in the top bar. Force it with `?mode=demo` in
the URL — worth doing when rehearsing, because you should rehearse against exactly what will be
on screen.

### Re-baking the demo payload

```bash
make demo-payload          # or: python scripts/build_demo_payload.py --run default_run
```

The payload is **generated by calling the same endpoints it replaces**. It is a recording, not
a fixture: nothing in it is hand-written, so a figure in Demo Mode is the figure the live API
would return. Re-bake it after any run that changes the artefacts, or the console will happily
serve yesterday's numbers.

## Deploying it as a static site

**Deployed at <https://razor-jet.vercel.app>.**

Demo Mode is the whole application with no backend, so the console deploys anywhere that
serves files. [`vercel.json`](vercel.json) configures Vercel; the same three decisions apply
to Netlify, Cloudflare Pages or S3.

**Set the project's Root Directory to `frontend`.** Everything else is in the config.

| Decision | Why |
| --- | --- |
| `VITE_MODE=demo` is set in `build.env` | Pins the mode at build time so the app never spends 1.2s probing for an API that was never deployed. Scoped to Vercel, so the container build — which *does* pair with an API — is untouched. It also takes precedence over `?mode=live`, so the deployment cannot be broken by a query string. |
| Rewrite `/((?!api/).*)` → `/index.html` | The console has real routes. Without this a judge who refreshes on `/defend` gets a 404, which reads as a broken site rather than a missing config. `/api` is excluded deliberately: rewriting it to the shell would return HTML with a 200, and a mode probe would read that as a live backend. |
| Cache headers mirror [`nginx.conf`](nginx.conf) | Hashed assets and fonts immutable for a year; `/demo/` revalidated, because the payload is replaced wholesale when the run changes and a cached copy would silently show yesterday's numbers; `index.html` never cached, since it points at the hashed assets. |

Verify a production bundle before trusting it — the two failure modes here are both invisible
on a dev server, which does not chunk and does not route:

```bash
VITE_MODE=demo npm run build
npx serve dist            # then deep-link straight to /loop and refresh
```

What is deliberately *not* on a static deploy: `RUN A ROUND NOW`, the `/deploy` latency probe,
and scoring. Those compute, they need the API, and each says so on screen rather than showing
a pre-recorded result. Everything else — every chart, table, drill-down and the guided tour —
works with no network at all.

## The rules this was built to

1. **No fabricated numbers.** Every figure traces to an artefact the pipeline wrote. There is
   no mock data, no placeholder, no `Math.random()`. The one exception is the counter rail on
   `/`, which tallies rows as they stream — and it says so, in the panel.
2. **Backend metric names, verbatim.** `recall_lost_to_red`, `zero_shot_recall`,
   `value_recall`, `n_sufficient`. They are not prettified, because judges cross-check against
   the CSVs and a renamed column is not greppable.
3. **Every panel names its source, and the name is a link.** `GET /api/runs/{run}/file/{name}`
   serves the artefact byte for byte. Checking a number costs one click.
4. **Missing is not zero.** A metric the run could not compute renders as an em dash. A recall
   of `null` on a vector with no positives is not `0.0%`.
5. **Every panel is error-boundaried.** Delete any CSV from `artifacts/default_run/` and that one
   panel says which file it wanted; every other panel on every route still renders.
6. **No external requests at runtime.** Fonts are self-hosted in `public/fonts/`. There is no
   CDN, no remote stylesheet, no remote image. It renders with the network cable pulled.


## Design notes

**Tokens, not hex.** `tailwind.config.js` contains no colour value — every one resolves to a
semantic CSS custom property. That is what makes both themes correct by construction rather
than by remembering to override things.

**Red means attacker or blocked.** It is never decoration. The structural accent is a cold
petrol cyan; money at risk gets violet, because rupees at stake are a different axis from
severity and read wrongly when merged into it.

**Presentation Mode** multiplies one variable, `--scale`, from which every type size derives,
and thickens `--stroke`. Nothing can drift out of sync because nothing else changes.

**Numbers are IBM Plex Mono with tabular figures.** In this domain ids and reason codes *are*
the vocabulary; setting them in mono is not decoration.

**A high separability probe is bad news, and the interface used to say the opposite.**
`/generate` previously rendered a high `derived_separability_recall` in green, captioned "that
is the detector doing work rather than the data leaking" — directly beside the same run's amber
warning saying the figure had cleared the pipeline's ceiling and that every detection metric
should be read as an upper bound. Both probes report recall at a 0.5% false-positive budget;
deployed card-fraud systems sit at 50–85%, and past the 92% ceiling in
`redteam/generate/fidelity.py` the generator flags its own data. The interpretation now lives in
`src/lib/fidelity.ts` beside the constants it depends on, the probes are drawn against the band
and the ceiling so the reading is structural rather than a caption, and `zeroed_checks` — a
component that bottomed out without tripping a flag — is surfaced instead of dropped.

## Known deviations from the brief

**No STEP-UP tier.** The brief asks for four outcomes including a step-up. The backend
produces three signals — a score against a calibrated threshold, an intent-guard block and an
agent-control block — and no second threshold is calibrated, reported or priced anywhere in
the pipeline. Inventing a step-up band would mean choosing a cut point no measurement supports
and then showing counts derived from it. The four classes the console shows are the four the
backend actually distinguishes, and the distinction the brief cares most about — a *provable*
block versus a *scored* one — is preserved and made the most visible thing in the table. See
`src/lib/decision.ts`.

**`RUN A ROUND NOW` runs red's half.** It fires a genome at the deployed model and reports
recall before and after on the same rows, live, in seconds. Blue's half — retrain on the
survivors, choose a countermeasure, re-measure — is minutes of model fitting and is not on the
critical path of a four-minute demo. The recorded rounds beside it are where blue's half is,
measured properly. The panel says which is which.

**`/deploy`'s latency figures are live-only.** Nothing in `artifacts/` records scoring latency,
and the pipeline's stage timings are batch figures over a whole run — quoting one as an inline
latency would be a category error. So the probe measures real decisions against a running model
and reports both server-side compute (from the API's own `latency_ms`) and browser round-trip,
kept separate. In Demo Mode the panel shows no number and says why. Everything else on `/deploy`
— the guard coverage, the loss bound, the cost model, the split — is read from artefacts and
works offline.

**Two Inspector panels are empty against the committed run.** `artifacts/default_run/` was
produced before `defend_counterfactuals.csv` and the `payer_id` / `channel` columns existed,
so the counterfactual section and the payer column show their empty states, naming the file
they wanted. That is the error-boundary contract working rather than a bug, but one more
pipeline run and a re-bake fixes it:

```bash
python -m redteam run --config configs/default.yaml --run-name default_run   # ~30 min
make demo-payload
```

Everything else on the committed run is live: 12 loop rounds, 9 promoted vectors, and a
convergence verdict of *diverging* — the loop reports that red gained faster than blue
recovered, and `/loop` says so rather than rounding it up into a success.
